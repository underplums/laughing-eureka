Задача: Построить модель, которая предсказывает вероятность ухода клиента из DAC в отток в течение месяца.

**Технические параметры:**

- Тип задачи: Бинарная классификация, модель выдаёт вероятность события в диапазоне 0-1.

- Целевая переменная: Клиент ушёл из DAC в отток, если в течение прогнозного окна перестал соответствовать критериям DAC: отсутствует покупка и/или отсутствует визит в мобильное приложение.

- Горизонт предсказания: 1 месяц.

- Входные данные: Аудитория клиентов, находящихся в DAC на дату расчёта.

- Единица скоринга: `contact_id`.

- Тип модели: `CatBoostClassifier`.

- Основные группы признаков:
  - история покупок;
  - история визитов в мобильное приложение;
  - recency-признаки по покупкам и app-активности;
  - частотные признаки за исторические окна;
  - агрегаты по чекам;
  - признаки регулярности активности;
  - статичные клиентские признаки;
  - история нахождения клиента в DAC.

- Исторические окна для сбора признаков: 1, 2, 3, 6, 12 и 24 месяца до даты расчёта.

- Основная метрика качества: F1-score.

- Дополнительные метрики качества:
  - ROC-AUC;
  - PR-AUC;
  - Precision;
  - Recall;
  - Lift;
  - Brier score.

- Порог классификации: подбирается по результатам валидации; для MVP может быть зафиксирован технический threshold.

- Валидация: тест на реальных клиентах в течение 1 месяца; разбивка предикта на 10 децилей для оценки фактической доли ухода в отток по каждому децилю.

- Выход модели: вероятность ухода клиента из DAC в отток в течение месяца, значение `score` от 0 до 1.

- Формат результата скоринга:
  - `model_name`;
  - `target`;
  - `version_id`;
  - `contact_id`;
  - `score`;
  - `model_inference_date`;
  - `model_train_date`.

Модель на выходе выдаёт для каждого клиента степень риска ухода из DAC в отток в диапазоне от 0 до 1. Чем выше значение, тем выше ожидаемая вероятность ухода клиента из DAC в течение следующего месяца.
